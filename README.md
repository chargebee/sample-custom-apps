# Marketplace Application

This is a Chargebee Marketplace application generated by the marketplace CLI.

## Architecture Overview

This application is designed to process Chargebee events in a serverless environment. The architecture abstracts infrastructure-specific details and provides a clean interface for handling business logic.

### Key Components

- **`index.mjs`** - Main event handler that processes incoming events
- **`internal/utility.mjs`** - Internal utilities for event parsing (do not modify)
- **`types.d.ts`** - TypeScript definitions for Chargebee events
- **`handlers/`** - Directory for your custom event handlers

## Type Definitions

This project includes TypeScript type definitions to help with development. The main types are defined in `types.d.ts`:

### EventRecord

The main event structure that your application will receive from Chargebee:

```typescript
interface EventRecord {
  api_version: string;           // API version (e.g., 'v2')
  content: Record<string, any>;  // Event content with customer/subscription data
  event_type: string;            // Event type (e.g., 'subscription_renewed')
  id: string;                    // Unique event identifier
  object: string;                // Object type (always 'event')
  occurred_at: number;           // When the event occurred (timestamp)
  source: string;                // Event source
  webhook_status: string;        // Webhook status
  webhooks: Array<{...}>;       // Webhook configurations
}
```

### Using Types in Your Handlers

Your event handlers receives the EventRecord. Here's how to use the types:

```javascript
/**
 * @param {import('./types.d.ts').EventRecord['content']} eventData
 */
export const handle = async (eventData) => {
  // Your IDE will now provide IntelliSense for eventData
  const subscriptionId = eventData.content.subscription.id;
  const customerId = eventData.content.customer.id;
  
  // Your business logic here...
};
```

**Note:** Event types are dynamically generated by Chargebee. Examples include `customer_created`, `subscription_created`, `subscription_renewed`, etc.

## Event Processing

The application automatically handles different event sources and provides a clean interface for processing Chargebee events.

### How It Works
1. **Hosting environment** receives an event from Chargebee
2. **`internal/utility.mjs`** automatically detects the event source and parses accordingly
3. **`index.mjs`** routes the parsed event to the appropriate handler
4. **Your handlers** receive clean Chargebee event data without infrastructure complexity

### Event Flow
```
Incoming Event → internal/utility.mjs → index.mjs → Your Handler
      ↓              ↓                    ↓           ↓
   Raw Data       Parse               Route      Business Logic
```

### Important Notes
- **`index.mjs`** and **`internal/utility.mjs`** are part of the core infrastructure
- **Do not modify** these files as they handle essential event processing
- Focus on writing your business logic in the **`handlers/`** directory

## Development

1. Install dependencies: `npm install`
2. Run tests: `npm test`
3. Deploy: Follow your deployment process

## Event Handler Structure

Each event handler should:
1. Export a `handle` function
2. Accept `eventData` as the first parameter (Chargebee event content)
3. Return a Promise with the processing result

Example:
```javascript
export const handle = async (eventData) => {
  // Process the event
  return { success: true, message: 'Processed successfully' };
};
```

## Adding New Event Handlers

1. Create a new file in the `handlers/` directory (e.g., `subscription_created.mjs`)
2. Export a `handle` function
3. Add the handler to `app-meta.json`:

```json
{
  "eventHandlers": {
    "subscription_created": "handlers/subscription_created"
  }
}
```
